# formatForge API audit — 2026-08-05

> Historical. The live contract is in [`storyforge-formatting-api.md`](./storyforge-formatting-api.md)
> (219 linked keys, contract version 11, host API v9). P1s listed below for
> disconnect restyle, mirroring, dropped disposers, and untyped import are fixed
> in HEAD. Do not treat this file as the current API description.

Cross-plugin audit of **formatForge ↔ storyForge**, with emphasis on the formatting host API, companion handoff, and theme transfer. Companion document: `storyForge/docs/api-audit-2026-08-05.md`.

**Scope:** bridge contract, soft-connect, theme import/export, palette ownership, capability gating.  
**Method:** code review of live sources + recent stress suites. Not a runtime Obsidian vault soak.

---

## Executive summary

1. formatForge is a **soft-connected companion**: it never writes vault paths itself for themes; it calls storyForge’s formatting API.
2. The live host is **API v8**, including validated batched linked updates.
3. storyForge’s exported `LINKED_FORMATTING_KEYS` is now the source of truth; formatForge consumes a generated 197-key contract.
4. Theme host updates now validate as one batch, save once and restyle once. Cross-plugin rollback is still impossible if FF’s later local save fails.
5. Live UI edits to SF-owned palette/sizes are **not mirrored into FF `data.json`**, so soft-disconnect can resurrect stale local values.
6. Capability gating in `FormattingExportModal` remains solid.
7. Removal of storyForge’s formatting transfer while formatForge is enabled is intentional product behaviour, not a defect.

## Findings

### [Resolved] Linked-key contract drift — generated shared contract

The audit found `editorScrollbarTrackColor` missing from formatForge. That key has since been retired from storyForge — the manuscript scrollbar track is always transparent so the document background shows through. storyForge now exports the canonical 197-key array, derives its own type from it, and generates formatForge’s contract via `sync-formatting-contract.mjs`. A parity check fails when the generated copy is stale.

### [P1] Live SF writes are not mirrored into FF local settings — `main.ts` `updatePalette` / size paths

While connected:

- `getPalette()` reads from storyForge;
- `updatePalette()` writes only to storyForge and returns without updating `ffSettings`.

Theme **apply** dual-writes sizes/palette into local via `importTextStylingSettings`, so apply-then-disconnect is OK. **UI-edit-then-disconnect** is not: getters fall back to stale `ffSettings`.

**Risk:** disabling or unloading storyForge after live palette/size edits silently reverts to the last FF-local snapshot.

### [Partially resolved] Cross-plugin theme apply atomicity — `formattingImport.ts`

At API v8, `applyFormattingDocument` sends linked settings and palette through `updateLinkedSettings`. storyForge validates the complete patch, saves once and restyles once. Older hosts retain the sequential fallback. One residual boundary remains: if the host batch succeeds and formatForge’s subsequent local save fails, there is no distributed rollback.

### [Resolved] Host API documentation updated to v8

Both host API documents now include the cumulative v2–v8 matrix, generated contract workflow, batch semantics and intentional UI ownership.

### [P2] Soft-connect null path drops disposers without calling them — `main.ts` `connectToStoryForge`

When `getSfFormattingApi()` returns null, FF nulls `unregisterCompanion` / contribution disposers without invoking them. Hot-reload identity change correctly unregisters first; the transient-null path does not.

**Risk:** usually fine if SF unload clears companion state; unsafe if the host instance still lives across a brief API gap.

### [P2] Local import accepts untyped values — `importTextStylingSettings`

Only checks object shape, known `DEFAULT_SETTINGS` keys, and that `customPaletteColors` is an array. No enum/type validation comparable to SF `LINKED_SETTING_VALIDATORS`.

**Risk:** hand-edited theme JSON can persist wrong types into FF `data.json` and break later style application.

### [P2] `getSfFormattingApi` gates on version ≥ 2, not on theme capabilities

Theme library UI correctly feature-detects functions. Version alone is not used for themes — good. But:

- a host at version 8 without methods would still soft-connect as a formatting companion;
- there is no shared helper like `hasThemeLibrary(api)` / `hasPresetManagement(api)`.

**Risk:** low today (SF always ships methods with its version), higher if another host or fork claims a high version. SF Protections can also hide Themes based on “FF enabled” even when FF is not connected or SF lacks preset APIs.

### [P2] Bridge omits `getCompanion`

storyForge’s `StoryForgeFormattingApi` exposes `getCompanion()`; formatForge’s `SfFormattingApi` does not. Not used by FF today, but the typed mirror is incomplete.

### [P2] No-op view contribution on connect — `main.ts` `connectToStoryForge`

formatForge registers `slot: "storyforge-panel"` with an empty render. Harmless, but adds churn on every rebind and suggests unfinished panel injection.

### [P3] Dual Confirmation / NamePrompt modal copies

`FormattingExportModal` and `ProtectionsModal` each embed private confirm/rename modals. Drift risk only.

### [P3] Companion registration `version: 1` never bumps

Harmless while the companion schema is stable; no negotiation exists if FF companion callbacks change shape.

### [P3] Apply defense-in-depth gap for interface section — `formattingImport.ts`

Parse strips size/palette keys from `storyForgeInterface`; apply only strips palette from that section. Safe if all callers parse first; programmatic docs could re-inject size keys.

## Strengths

- Soft-connect with retry + API identity rebind (`hostConnectRetry` / `connectToStoryForge`).
- Optional method gating in the themes modal (preset vs archive vs rename/delete).
- Versioned formatting documents (v2) with v1 migration, section metadata checks, palette stripping.
- Apply order: validated host writes before local FF persist; empty apply rejected.
- No direct vault writes from formatForge for themes — storage stays behind storyForge’s write guard.
- Unknown host keys cannot be injected: apply intersects with live `getLinkedSettings()`.
- Solid stress coverage: export combinations, import ownership, disconnect/reconnect, bad linked abort.

## Recommended follow-ups

1. Mirror SF-owned palette/size/scrollbar writes into `ffSettings` (or sync snapshot on unbind).
2. Validate formatForge-local imported setting types before persistence.
3. Extract `hasThemeLibrary` / `hasPresetManagement` and test capability matrices.
4. Always invoke companion disposers before clearing soft-connect refs.
5. Add `check:formatting-contract` and both stress suites to CI.
